球グループ AABB キャッシュの比較（2026-09-26）

これは最初の実装の測定記録。現在のコードには追加の生成処理最適化が入っている。
最新の3ビルド比較は [aabb_cache_optimization.md](aabb_cache_optimization.md) を参照。

今回の `example/bench` の3ケースでは高速化しなかった。座標計算と AABB
集約をまとめた実装でも、平均時間は Panda +2.5%、Panda difficult +8.9%、
Fetch +7.5% だった。この3ケースの最適化として、そのまま採用する根拠は得られなかった。
実装は検討・レビュー用に残している。

対象は現在の `7574426caf41b9964f3acb47cc89f05728f05288`。
`aabb_idea.html` が参照する certificate 実装はこの checkout に含まれず、
ユーザーの指定に従い通常の外部衝突判定を比較した。certificate ON/OFF の比較ではない。

| ケース | 変更前の平均 ms | AABB の平均 ms | 時間の増加 | 変更前 / AABB の中央値 ms |
| --- | ---: | ---: | ---: | ---: |
| Panda | 0.21834 | 0.22382 | +2.51% | 0.19526 / 0.19979 |
| Panda difficult | 0.81301 | 0.88503 | +8.86% | 0.70763 / 0.76795 |
| Fetch | 0.81012 | 0.87113 | +7.53% | 0.66495 / 0.71597 |

各ケース・各ビルド **50,000 solve**（既存 example の5倍）。seed 101〜105 を
別プロセスで使用し、各 seed で200回ウォームアップ後に10,000回計測した。
奇数 seed は変更前→AABB、偶数 seed は AABB→変更前の順序。
ベンチマークは並行実行せず、同じ CPU 2 に固定した。

同一 seed の平均時間の増加幅は、Panda +1.38〜+3.74%、difficult
+3.20〜+19.34%、Fetch +4.61〜+13.38%。difficult / Fetch は実行間の揺れが
残っているため、上表の悪化率を精密な定数とはみなさない。全15組で増加した。
外れた実行や遅いサンプルは除外していない。

時間は元の example と同じ `OMPLSolverResult.time_elapsed`。
内部計時でも平均はそれぞれ 0.19981→0.20532 ms、0.78412→0.85430 ms、
0.78147→0.83975 ms で、同じ傾向だった。

条件は RRTConnect、`algorithm_range=2.0`、refinement なし、Box validator、
全関節の幅 0.05。scene、開始・目標姿勢、ロボットモデルは元の3ケースと同じ。
AMD Ryzen 7 7840HS、turbo 有効、GCC 9.4.0、Release / `-O3 -DNDEBUG -flto`、
`EIGEN_DONT_VECTORIZE`、Python 3.8.10、nanobind 2.9.2、OMPL 1.6。
`OPENBLAS_NUM_THREADS=1`、`OMP_NUM_THREADS=1`。
変更前後は同じ CMake ビルド設定を使い、最終時間計測には診断用カウンタを含めていない。

実装は `SphereGroup` に半径込みのワールド AABB と有効性を保持する。
未作成なら従来の main sphere による AABB / 形状判定を先に行い、必要になった
グループだけで座標計算と min/max 集約をまとめる。作成後は最初の AABB 判定を
置き換え、main sphere の形状判定と sub sphere の判定順序は維持する。
既存の座標キャッシュだけがある場合も一度だけ集約する。自己衝突だけの座標計算には
集約費用を追加していない。

姿勢変更や球順序変更時は既存の `clear_cache()` で一緒に無効化する。
境界は両端の絶対値に比例した丸め余裕で外側に広げる。`p + r` が打ち消し合う
場合、結果の `nextafter` だけでは旧判定の `object.lb - r` との整合性を保てない
ため、このケースを回帰テストに含めた。非有限値・負の半径・オーバーフローでは
AABB を無効として従来の判定へ戻る。無効状態で min/max を毎回やり直さない。

全150,000組で成功し、**判定回数と経路の SHA-256 が変更前後で完全一致**した。
Python テスト全129件が通過（NumPy / OMPL seed 42）。追加11件には姿勢の変更と復元、
後続障害物での衝突、半径の違い、回転、Ground の無限境界、接触前後、
大きな座標、打ち消し、非有限値、空グループを含む。
これはテストした入力での一致であり、近似 FK を含めた全入力の数値的同値の証明ではない。

最初の seed 未固定のテスト実行では、既存の OMPL shortcut テストが1件失敗した。
失敗した姿勢は旧版・新版とも同じ衝突判定と制約値だった。
seed 42 で OMPL テスト25件を旧版・新版それぞれ実行すると両方通過し、
その後の新版の全テストも通過した。

別の診断用ビルドで seed 101 の10,000 solve + warmup 200回を調べた。
同じ検査点で旧ループも評価して回数だけ数え、診断版の経路・判定回数も一致した。

| --- | ---: | ---: | ---: | ---: | ---: |
| Panda | 1,152,417 | 11,684,710 | 9,252,964 | 3,211,444 | 65.3% |
| Panda difficult | 6,836,584 | 69,543,478 | 54,675,891 | 15,411,551 | 71.8% |

AABB は多くの詳細判定を省いている。しかし各姿勢で、平均7〜10球のグループに対し
集約・数値チェック・追加の分岐が必要になる。今回の計測では、その追加費用全体を
省いた球判定の費用で回収できなかった。生成時間だけを分離計測した結果ではない。
座標計算後に別ループで集約する初期版も試し、予備計測では3ケースとも約3〜5%遅かった。

形状を限定した補助実験も行った。x=-1〜1 に半径0.05の球128個を並べた1グループを
使い、`is_valid` を10万回×3セット、実行順を交互にして測定した。
単位は1回あたり µs（Python 呼び出しを含む、3セット平均）。

| 配置 | 変更前 | AABB | 結果 |
| --- | ---: | ---: | --- |
| y=0.5 の近傍に小箱32個 | 4.248 | 1.047 | 約4.1倍高速 |
| y=5.0 の遠方に小箱32個 | 0.395 | 0.383 | ほぼ同程度、生成に到達しない |
| 最初の球に衝突する小箱1個 | 0.520 | 0.994 | 約1.9倍の時間 |

細長いグループで多数の近傍障害物を省く用途には効果がある。
汎用の高速化として採用するなら、生成費用をさらに下げるか、球数・障害物数等で
適用を絞る検討が必要になる。それらの選択則は今回の実装には加えていない。

再計測には [compare_aabb.py](../../example/bench/compare_aabb.py) を使う。
変更前後の拡張モジュールを別々に保存し、必ず新しい Python プロセスで実行する。
この作業環境では `.cache/aabb/baseline/` と `.cache/aabb/fused/` に保存済み。
インストール済みの拡張モジュールは変更していない。

```bash
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 .venv/bin/python \
  example/bench/compare_aabb.py \
  --module .cache/aabb/baseline/_plainmp.cpython-38-x86_64-linux-gnu.so \
  --case panda --samples 10000 --warmup 200 --seed 101 --cpu 2 \
  --output .cache/aabb/recheck_panda_101_baseline.json
```

`--case` は `panda` / `panda_difficult` / `fetch`。
`--module` を `fused` に替えて同じ seed を実行する。
seed 101〜105、3ケースを上記順序で測れば本計測と同じサンプル構成になる。
出力 JSON の各行は wall time、内部時間、判定回数、経路ハッシュ。

集計・各 seed の結果・診断回数・補助実験の値・バイナリ SHA-256 は
[aabb_cache.json](aabb_cache.json) に保存した。
全サンプルはローカルの `.cache/aabb/final/`、診断ビルド生成スクリプトは
`.cache/aabb/build_diagnostic.py`、補助実験は `.cache/aabb/synthetic.py` にある。
これらの `.cache` 内ファイルは Git 管理対象外。
